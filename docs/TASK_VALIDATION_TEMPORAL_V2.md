# Task-Level Validation V2 — Multi-seed Temporal Robustness

**Run status:** protocol and reference implementation added; user execution on Android Termux is pending. No V2 accuracy or learning benefit is claimed yet.
**Benchmark:** JARVIS_TEMPORAL_ROBUSTNESS_V2
**Date prepared:** 7 November 2026

## Objective

Extend the first overlapping temporal challenge with more examples, multiple deterministic datasets, a wider shared input-strength range and a control that isolates the reward-modulation contribution in R-STDP. The benchmark remains a reference experiment for one Adaptive LIF-DT neuron and one excitatory synapse. The STARTER profile is not modified.

## Pre-registered protocol

- Four deterministic independent runs, keyed by seeds 104729, 130363, 155921 and 181081.
- Each run has 16 BURST and 16 SPARSE training episodes, plus 20 BURST and 20 SPARSE held-out episodes.
- Each episode contains three input pulses, two inter-pulse gaps and three per-pulse strengths.
- BURST gaps are generated in the inclusive range 4–8 ms; SPARSE gaps are generated in 7–11 ms. Their per-gap ranges overlap at 7–8 ms.
- Both classes share the same strength grid: 0.80, 0.85, 0.90, 0.95 and 1.00. Strength is a nuisance variable, not the class label.
- Candidate inputs are generated by a SHA-256-derived deterministic function of seed, split, label, sample index and collision retry. There is no run-time randomness. Exact full input signatures are unique within each run and disjoint between training and held-out splits.
- The neuron starts from rest for each episode. Synaptic state persists across training episodes within each run and condition. Episodes are separated by 2,000 ms of model time.
- Initial synaptic weight is 0.5. The decision rule is frozen: one or more output spikes means BURST; zero means SPARSE.
- Held-out evaluation is inference-only for every condition: weights are frozen and there are no STDP, eligibility or reward updates.

Each condition sees exactly the same data for a given seed.

## Compared conditions

1. **FIXED:** no synaptic updates.
2. **STDP:** pair-based excitatory STDP after each pulse; no class label is supplied to the local rule.
3. **R-STDP:** eligibility updates after each pulse; after the complete episode the evaluator sends reward 1.0 for a correct prediction and 0.0 for an incorrect prediction.
4. **R-STDP neutral-reward control:** the same eligibility updates, followed by a reward equal to the current reward baseline. This produces zero reward prediction error, consumes the episode eligibility and controls for the presence of the R-STDP machinery without positive or negative reward modulation. It is not an absence-of-evaluator condition.

The direct reward question is therefore tested by comparing rewarded R-STDP with the neutral-reward control, in addition to comparing both against FIXED and ordinary STDP.

## Metrics and report structure

For each run and for all runs pooled, the JSON report contains train and held-out confusion counts (TP, FP, TN, FN), accuracy, precision/recall/F1 for each class, specificity, balanced accuracy and macro-F1. It also records per-seed held-out accuracy, sample standard deviation across the four runs, training weight trajectories, reward values/modulation and the held-out weight-freeze check.

The reward-effect section reports per-seed and across-run differences between R-STDP and the neutral-reward control. An apparent reward benefit should be visible across multiple seeds and should not be inferred from weight changes alone.

## Run on Android Termux

From the repository root:

~~~sh
python3 -m tools.task_validation.temporal_robustness_v2 > temporal_robustness_v2_report.json
python3 -m unittest discover -s tools -t . -v
~~~

To print a compact summary without a long one-line command:

~~~sh
python3 - <<'PY'
import json

with open("temporal_robustness_v2_report.json") as f:
    report = json.load(f)

print(report["benchmark"])
for condition in report["aggregate_conditions"]:
    held = condition["held_out"]
    spread = condition["held_out_accuracy_across_runs"]
    print(
        condition["condition"],
        "accuracy:", held["accuracy"],
        "balanced_accuracy:", held["balanced_accuracy"],
        "macro_f1:", held["macro_f1"],
        "TP/FP/TN/FN:", held["tp"], held["fp"], held["tn"], held["fn"],
        "per-run accuracy mean/stdev:", spread["mean"], spread["sample_stdev"],
    )

print("Reward effect:", report["reward_effect"])
PY
~~~

The summary is followed by detailed per-run episode traces in the JSON file.

## Interpretation limits

- Four deterministic seeds provide repeated challenge sets, not a statistically powered population estimate or confidence interval.
- Overlapping per-gap ranges make some input components ambiguous. The report should be read as a controlled engineering comparison, not a claim of universal burst/sparse recognition.
- The neutral-reward control is a zero-modulation comparator, not a no-feedback condition.
- If rewarded R-STDP improves accuracy but reduces SPARSE specificity, the trade-off must be reported rather than called an unconditional improvement.
- STDP and R-STDP may be limited by the one-neuron/one-synapse architecture or the frozen output rule. Do not tune STARTER to this dataset.
- A successful Python reference run is not production-runtime validation, biological equivalence, consciousness or general intelligence.
- Do not run application builds or CI/GitHub Actions as part of this experiment.
