# Первый Android-прототип JARVIS — сборка и установка

**Ветка:** `experiment/jarvis-integrated-prototype-v1`  
**Цель:** получить первый устанавливаемый debug APK, не дожидаясь завершения исследовательских этапов JNVM/LRU, полной синхронизации и автономного агента.

## Что входит в первый прототип

- Нативный Android-интерфейс Jetpack Compose.
- Диалог и локальная история на устройстве.
- In-process Kotlin Core, ANS-100 signal pass и локальные эвристические компоненты, уже подключённые в Android UI.
- Ограниченная локальная память и пользовательские заметки.
- Необязательная локальная языковая модель LiteRT-LM / Qwen3-0.6B INT4, если пользователь импортирует совместимый файл модели.
- Без Termux приложение должно открываться и предоставлять ограниченный fallback. Fallback не является универсальной языковой моделью и не отвечает произвольно на любые вопросы.
- Безопасный режим: внешний shell, произвольное управление устройством и автономные внешние действия не включаются.

## Сборка через GitHub Actions

Ветка не содержит Gradle Wrapper. Workflow устанавливает Gradle 8.9 на GitHub-hosted runner, использует JDK 17 и стандартный предустановленный Android SDK runner image, затем через sdkmanager устанавливает Android SDK 35. Не используем устаревший пакет SDK `tools`. Это не создаёт локальный `gradlew`; wrapper можно добавить отдельным шагом после получения первого артефакта.

Workflow: `.github/workflows/android-prototype.yml`.

Он автоматически запускается при изменениях Android/build-файлов в этой ветке и поддерживает ручной запуск через GitHub Actions → Android first prototype → Run workflow.

Команда сборки:

```sh
gradle --no-daemon --stacktrace :app:assembleDebug
```

Ожидаемый артефакт:

```
app/build/outputs/apk/debug/app-debug.apk
```

Workflow загружает APK как артефакт `jarvis-ans100-debug-apk` на 7 дней.

## Как скачать APK на Android

1. Открой репозиторий GitHub и переключись на `experiment/jarvis-integrated-prototype-v1`.
2. Открой вкладку Actions.
3. Выбери успешный запуск **Android first prototype**.
4. Внизу страницы найди Artifacts и скачай `jarvis-ans100-debug-apk`.
5. Распакуй ZIP и открой `app-debug.apk`.
6. Разреши установку приложения из этого источника, если Android попросит.
7. Установи и запусти JARVIS.

Если запуск workflow не появился, проверь, разрешены ли GitHub Actions для репозитория и доступны ли минуты Actions. Если runner не стартовал из-за квоты/политики, это BLOCKED, а не ошибка Kotlin-кода.

## Локальная модель

Модельные веса не включены в APK. Это сделано, чтобы не превращать приложение в огромный установочный пакет. После установки открой в JARVIS раздел модели и импортируй совместимый файл Qwen3-0.6B INT4 LiteRT-LM, если он у тебя есть. Ветка содержит проверку доступной памяти перед инициализацией модели; успешная сборка APK не доказывает, что модель запустится на конкретном телефоне.

Без импортированной модели должен использоваться ограниченный offline fallback. Он нужен для проверки интерфейса и жизненного цикла приложения, а не для полноценного общения.

## Что не входит в условие первого APK

Не блокируем первую сборку завершением следующих исследовательских задач:

- интеграция Python JNVM/LRU с атомарным сетевым координатором;
- автоматическая Android↔PC синхронизация;
- полноценное самостоятельное рассуждение и безопасный исполнитель действий;
- видимый PC-браузер и проверка его интеграции;
- масштабные 10k-бенчмарки и измерения на устройстве.

Эти задачи продолжаются после получения первого устанавливаемого прототипа. Не объявлять их готовыми на основании успешной сборки.

## Что доказывает первый build

Успешный `:app:assembleDebug` подтверждает только, что Android debug APK был собран на GitHub runner. Он не подтверждает установку, отсутствие runtime-crash, работу LiteRT-LM, корректность обучения, качество русского языка, синхронизацию или безопасность внешних действий.

После скачивания APK отдельно проверяются установка и первый запуск на Android 15, локальный чат без модели, история, сохранение памяти и только затем импорт/запуск модели.
