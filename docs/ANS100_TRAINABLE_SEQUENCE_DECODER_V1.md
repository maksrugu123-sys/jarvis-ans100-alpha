# ANS-100 Trainable Sequence Decoder V1

## Status

The Android branch contains a small trainable Elman recurrent neural network for next-token prediction. It is an experimental local component, not a pretrained Russian language model and not evidence of general language understanding.

The decoder is wired into the Android conversation response generator, but it only takes the learned-generation path after a model has been explicitly trained, restored from a valid snapshot, and its output passes conservative token-count and confidence gates. Until then, the existing bounded ANS response strategy remains active.

## Model

- Tokenizer: bounded Unicode word and punctuation tokenizer.
- Vocabulary: reserved BOS, EOS and UNK tokens plus a frequency-ranked training vocabulary.
- Network: one recurrent hidden layer with tanh activation.
- Objective: next-token categorical cross-entropy.
- Training: sequence back-propagation through time with clipped gradients.
- Decoding: bounded greedy autoregressive generation.
- Limits: at most 256 training examples, 64 tokens per example, 512 vocabulary entries, 64 hidden units and 48 generated tokens.

There are no pretrained weights, cloud calls, Qwen calls, prompt templates or hidden language-model dependencies in this decoder.

## Persistence

The model snapshot stores its format version, architecture size, vocabulary, input/recurrent/output matrices and biases. The snapshot is validated completely before it replaces the active model.

Android stores snapshots in an app-private file through AtomicFile; it does not place large neural matrices in SharedPreferences. The language module trains a candidate model and publishes it as active only after the durable snapshot write succeeds. A malformed or unreadable snapshot is not silently overwritten.

## Learning safety

Incremental fine-tuning is accepted only for:
- an explicit user correction; or
- an independently verified external outcome.

The following are not accepted as labels:
- text generated by the decoder itself;
- passive user behavior or inferred engagement.

This prevents the system from reinforcing its own unverified output as if it were ground truth.

Correction learning uses the prompt as recurrent context and supervises only the corrected continuation (plus its end marker). Prompt tokens are not treated as desired output labels, while gradients can still flow through the prompt state so the network can adapt the context representation.

## Chat integration

ANS100NeuralResponseGenerator can call the trainable decoder after a model has been loaded or explicitly trained. Capability, greeting, farewell and correction paths remain deterministic. Learned text is accepted only when it contains at least two generated tokens and mean token confidence is at least 0.25. The confidence is a decoder score, not a calibrated probability of factual correctness.

The ViewModel exposes explicit training, correction-feedback, generation and status methods. No automatic training corpus is bundled: training examples must be supplied deliberately. Until a sufficiently broad and independently reviewed Russian corpus is available, output quality and generalization are not established.

## Build policy

The Android GitHub Actions workflow currently has only workflow_dispatch. Pushes to the working branch no longer start automatic tests or APK builds. A manual run remains available from the GitHub Actions page. The Windows package workflow is also manual-only.
