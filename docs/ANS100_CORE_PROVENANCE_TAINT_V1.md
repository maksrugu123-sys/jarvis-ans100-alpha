# ANS-100 Core Provenance Taint V1

Status: implemented as an experimental guard; Android tests are authored but not executed in this change.

## Purpose

The canonical four-class readout (YES / NO / UNKNOWN / CONFLICT) must not learn from a signal whose neural activity was influenced by heuristic Core output. Excluding the six Core candidate input IDs is insufficient: a heuristic event can activate an intermediate neuron and affect later spikes through ordinary synapses.

This guard tracks taint through the event-driven LIF runtime and fails closed at both training eligibility and answer decoding.

## Origin classification

At the typed-evidence adapter boundary, an event is Core-tainted when its record has `HEURISTIC` status or comes from `CORE_UNDERSTANDING` / `CORE_REASONING_PLAN`.

Raw user text, observed message structure, explicitly approved memory references, verified tool results, and the separate concept-input trace are not marked Core-tainted by this rule. This is a provenance classification, not a claim that those inputs are inherently correct.

Both `beginHybridTurn` and `scheduleHybridEvidence` verify that event taint flags exactly match the accompanying evidence trace. A caller cannot silently relabel a heuristic trace as clean.

## Propagation semantics

- `AndroidNeuronEvent.coreTainted` records the origin bit.
- A neuron becomes tainted if it was already tainted in this turn or receives at least one tainted event at the current timestamp.
- Taint is sticky for that neuron for the remainder of the isolated turn, including when a tainted input does not immediately cause a spike.
- Every event generated by a tainted neuron inherits the taint bit. This carries taint through arbitrary multi-hop synaptic paths and mixed clean/tainted inputs.
- The neuron taint bit and queued-event taint bit are committed in the same SQLite timestamp transaction as membrane state and event queue updates.
- Taint is cleared only by `beginHybridTurn`, after the previous event queue has drained and all membrane/adaptation/refractory state is reset.

## Persistence and migration

SQLite schema version is 10. The `neurons.core_tainted` and `events.core_tainted` columns preserve the taint state across process restarts and partial inference passes.

When upgrading a version-9 database, pending events are marked tainted because their origin cannot be reconstructed. Neurons with residual potential, adaptation, or refractory state are also marked tainted. The next isolated hybrid turn resets this residual state before accepting new evidence. Learned connection weights and feedback records are preserved.

## Enforcement points

1. Input scheduling rejects mismatches between typed provenance and the event taint bit.
2. The runtime returns every neuron that became tainted, including neurons that spiked earlier and were contaminated later; the ViewModel aggregates this set across every partial run pass.
3. The canonical decoder excludes every spike from a neuron that became tainted at any point in the turn, including an earlier spike emitted before contamination. If all canonical output spikes are tainted, the result is `NO_LEARNED_SIGNAL`, not a guessed answer.
4. SQLite filters tainted source neurons out of canonical-readout eligibility before feedback can create or update the four class synapses.

## Tests added

- Core heuristic events are marked tainted at the input adapter.
- A forged batch that strips the taint flag is rejected before scheduling.
- A tainted event propagates over a real synapse; the queued event and downstream tainted state survive closing and reopening the SQLite-backed network; the downstream neuron is denied canonical-readout eligibility.
- A clean neural spike remains eligible.
- The decoder ignores tainted canonical output spikes and abstains when only tainted outputs fired.

These tests have not been run as part of this change. No Android build or CI workflow was launched.

## Limits and next verification

This is a conservative provenance firewall, not proof of general semantic independence. It protects paths whose input records preserve their declared provenance. Any future input adapter must classify its source correctly and must not manufacture a clean label for heuristic-derived content. New adapters should receive equivalent forged-label tests.

The current runtime still consumes a mixed evidence batch; Core heuristics may continue to influence non-readout populations and the verbal response path. The guard prevents that tainted activity from training or directly deciding through the canonical readout. It does not yet make the network a complete autonomous reasoning system.

The next experiment should run identical held-out tasks with:
- ANS-100 canonical readout using only provenance-clean spikes;
- Transformer-only inference;
- simple trainable and random control baselines.

Report accuracy, abstention/coverage, compositional and concept-disjoint transfer, latency, peak RAM, and model/runtime size. Do not compare until each system has emitted real predictions for the same examples.
